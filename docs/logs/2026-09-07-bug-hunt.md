# Zydeco bug hunt, 2026-09-07

Target: `~/code/zydeco/impl` on `main` at `e00b91f0` (v0.3.0), release binary, macOS arm64 host,
native amd64 executables run under Rosetta. Every finding below was reproduced by hand after the
probe that found it reported. Reproduction programs live in `~/.claude/jobs/17fab1ae/tmp/{sem,review,fuzz,diff,gc}/`
(job-scoped; copy out anything worth keeping). Already known and excluded: the release-only
`pop_stack` bug, fixed in d54ec327.

Method: five probes. Semantic probes of new language features; targeted review of the 2026-09-04..06
commits; frontend fuzzing (53,827 mutants of 122 seeds through `check`, ~4k through `run`, ~18k through
`fmt` twice, 310 hand cases); differential testing of interpreter vs amd64 vs wasm-am vs wasm-sps
(136 corpus runs plus targeted programs); full audit of `runtime/gc.rs`, `runtime/stub.rs`,
`lang/amd64/src/emit.rs` with stress programs.

## A. Native backend and GC (priority area)

### A1. Rebuild into an existing `--build-dir` publishes the previous executable
Build a program, run it, edit a constant, rebuild into the same dir: build exits 0, `<name>.s` has the
new constant, `<name>.exe` still runs the old code (`-x` too). `runtime/build.rs:3-6` emits only
`rerun-if-env-changed`, never `cargo:rerun-if-changed` for `libzy<name>.a`; `cli/src/native.rs:108-113`
`publish_executable` renames cargo's uplifted `target/<triple>/debug/main`, but the real artifact
`deps/main-<hash>` stays and is re-uplifted unchanged next time. Validated fix in a scratch copy:
`println!("cargo:rerun-if-changed={dir}/lib{lib}.a")` in build.rs. Anyone iterating on a native test
case in one build dir is silently running the previous version.

### A2. Collection cost is O(pointer words x all blocks in from-space)
`runtime/gc.rs:281-308` `containing_block` walks every header from `from_base` to `from_used` (live and
dead, ~65k when the 1 MiB semispace is full) for every even in-range word forwarded (`forward`,
gc.rs:246). Non-tail recursion depth 10k: 4.4 s native vs 0.06 s interpreter; depth 20k: 56 s;
depth 100k killed at 900 s (RSS 4.4 MB, so not memory pressure). 5,000-cell list: 3.1 s native vs
0.1 s wasm; 20,000 cells > 60 s. Output correct whenever it finishes. Fix: per-collection block-start
bitmap or sorted offset table with binary search; or, since interior pointers are never produced (A7),
read the header at `value - HEADER_BYTES` in O(1).

### A3. 1 MiB fixed semispace, undocumented hard limit
`runtime/stub.rs:1380 HEAP_SPACE_BYTES = 1024*1024`. A live 20,000-cell Int64 list exits 1 with
`Zydeco runtime: out of memory (requested 1 words; 1048576 of 1048576 bytes remain live)`; 14,000
succeeds. Graceful, but DESIGN.md "Current Limitations" only mentions the WASM heaps.

### A4. Abandoned `args/fold` tails exhaust the 256-slot host root table (native only)
`stub.rs:499-518` `into_thunk` registers two host roots per pending tail; `from_environment`
(520-530) unregisters only if the tail is resumed. `HOST_ROOT_CAPACITY = 256` (stub.rs:1382).
300 calls to `args/fold` that take only the first argument: native `out of memory (host root table is
full)`, exit 1; interpreter exits 0. The `Box<ArgumentFold>` leaks too.

### A5. Strings and Bytes are never freed on the native runtime
`HostString::leak` / `HostBytes::leak` (stub.rs:200, 236) `Box::into_raw` every result of append,
to_string, slice, literal; gc.rs:292 treats them as foreign pointers. 2,000 appends of 100 chars: max
RSS 215 MB native vs 16 MB interpreter; 4,000 byte appends: 524 MB vs 17 MB.

### A6. Latent: stack-allocated product emitter is wrong (dead code today)
`lang/amd64/src/emit.rs:825-871`: `sub rsp, 8*arity; mov rax, rsp`, then the loop pops from the
freshly reserved region (garbage) instead of the pushed elements, leaves the elements on the stack,
and the parity accounting assumes they were consumed. Unreachable because
`LocalUnboxing::stack_values` (`lang/assembly/src/unbox.rs:21`) is never populated, only read at
`lower.rs:252,299`. Delete or fix before enabling escape analysis for real.

### A7. Latent: interior-pointer ("product suffix") paths are untested
`elements < arity` layouts (emit.rs:840-857, 887-898; gc.rs interior-offset forwarding) are never
produced: `ProductLayout { arity: items.len() }` at `sps_low/convert.rs:140-154` and `sps/lower.rs:741`.
This is what makes the O(1) fix in A2 safe.

### A8. `build -x` reports exit 0 when the executable dies by signal
`cli/src/main.rs:270`: `executable.run(&[])?.code().unwrap_or(0)`. SIGABRT (134) from a native
division by zero or a refutable-pattern abort shows as `exit=0` through `-x`. Masks native crashes in
any workflow relying on `-x`.

Audited and correct: Int64 tag boundaries at +-2^62, +-2^62+-1, 2^63-1, -2^63 via literals, arithmetic
crossings, eq/lt/gt, literal-pattern match on boxed values, MIN/-1, negative mod; UInt64 at 2^63-1,
2^63, 2^64-1; all narrow widths wrap identically; NaN/+-inf/-0 printing and compare; Float32 immediate
encoding; odd=immediate/even=pointer honored at every emitted immediate; every allocation site
allocates before popping operands so operands stay rooted; environment root ranges consistent;
forwarding restores header tags; FFI Bytes buffers are Rust-owned so GC cannot move them under C;
closures, comatch objects, mutual recursion, ret-returned products all survive dozens of collections;
outputs deterministic across runs. No segfault, bus error, or memory corruption was produced by any
program.

## B. Compiler (all compiled backends)

### B1. Demand analysis drops `let` bindings that lowering still references (panic on valid programs)
Introduced by 72ff9d0a. `lang/stackir/src/sps/demand.rs:221-227` visits a `Do` bindee under the
binder's demand, so `do _ <- ...` marks nothing inside as demanded; `lower.rs:853-855, 1029-1031` drop
any `let` whose binder is Absent, but the `do` bindee is still lowered in full. Result: dangling
variable, `panic!` at `lang/stackir/src/sps/check.rs:221` ("stack IR root ... is not closed").
All run correctly on the interpreter and crash `zydeco build` for every target:
```
let z = 7 in do _ <- ret z; ! process/exit 3
let w = 7 in do _ <- ret (w, 6); ! process/exit 3
let w = 7 in do _ <- (fn (y : Int64) => ret w) 3; ! process/exit 3
let w = 7 in let t = { ret w } in do _ <- ret t; ! process/exit 3
let val k (_ : Int64) : Int64 = 0 in let w = 5 in let r = k w in ! process/exit r
```
Variant misreported as a source error: `let val k (x : Int64) : Int64 = x in do _ <- ret (k 1); ...`
gives "value application does not statically resolve to a definition" (demand.rs:320 visits the head
with Absent, so the `let val` is skipped before `record_value_function_binding`). Fix: a `Do` with an
Absent binder must still visit its bindee as Used.

### B2. Value-function unfolding is exponential; 16 lines overflow the compiler stack
`lower.rs:648-676` `unfold_value_application` re-lowers the callee body at every use. Chain where
`g_n x = g_{n-1} (g_{n-1} x)`: 10 levels emit 4.3 MB of SPS; 16 levels abort with "thread 'main' has
overflowed its stack"; interpreter runs 20 levels in 0.5 s. Needs sharing or a bound.

### B3. Alias of a partial application does not resolve in lowering
`let h = f 1 in let g = h in let (a, b) = g 2 in ...` runs on the interpreter, rejected by lowering.
`lang/stackir/src/sps/value_functions.rs:89-101` `is_unfoldable_definition` only handles a bindee that
is itself an application, not a `Var` chasing to one. `h 2` and `g = f; g 1 2` both work.

### B4. Refutable patterns accepted in irrefutable positions; native ICE
Coverage runs only on `match`/`comatch`. `let +T() = b`, `let 5 = n`, `fn (0 : Int64)`,
`do (0, x) <- ...`, `param (0 : Int64) that` all pass `check`. Interpreter: Rust panic
`lang/dynamics/src/eval.rs:267` "pattern match failed in let: ()" (payload prints `()`). Native:
constructor patterns ICE at `lang/assembly/src/lower.rs:153`; literal variants compile and SIGABRT.
`lib/tests/core/literal-pattern.zy` deliberately uses `let 5 = five`, so if refutable `let` is intended
the missing piece is a non-panicking runtime failure.

### B5. Value-function totality hole
value-pi.md says application cannot fail; only parameters are checked for irrefutability.
`let val f (x : Int64) : Int64 = let 0 = x in 1` checks (also with `--lint-types`), panics at
`eval.rs:173` when applied to 3; native ICE `lang/stackir/src/sps/lower.rs:362`. A view `f ~> y` built
from such an `f` makes the exhaustiveness argument unsound.

### B6. Checker stack overflow on deep nesting
~1,500 nested `let`s, ~2,000 nested `fn`/thunks, or ~8,000 nested type applications abort the checker
(exit 134) on the 8 MiB main thread. Parsing is fine (lalrpop explicit stack). No large-stack thread
anywhere in `cli/src` or `lang`. This is also the ceiling B2 hits.

## C. Checker and desugarer ICEs on malformed input

- C1. `fix (x : Int64) => ...` (any non-application binder type): `lang/statics/src/check/mod.rs:6786`
  `let Type::App(..) = ... else { unreachable!() }`.
- C2. Anonymous `def ! (M : VType) (x : M) : Ret M = ret x that ...`: `mod.rs:5188` "resolved variable
  `M` reached the checker before its binder" (parameter binders registered in a different order than the
  named form).
- C3. `codata | .foo .bar : OS end`: explicit `panic!` at `lang/surface/src/bitter/desugar.rs:1019`.
- C4. `@[monadic]` block with `Monad` shadowed by a non-codata type of the right kind:
  `lang/statics/src/elaborate/monadic/construct.rs:1125`.
- C5. Value hole passes `check`, panics in `run`: `let x : Int64 = _ in ...` checks with exit 0
  (prints "Hole Solutions"), then `lang/dynamics/src/eval.rs:165` "Hole in value". Only `! _` / `ret _`
  are rejected. 566 fuzz mutants hit this one site.
- C6. Integer `div`/`mod` by zero is a Rust panic on both backends (exit 101 / SIGABRT), contradicting
  README "malformed input does not panic the host runtime".

## D. Interpreter

- D1. `stdio/write_error` goes to stdout: `lang/dynamics/src/impls.rs:736` and `:928` map
  `WriterHandle::STDOUT | STDERR` both to `output`. Native and wasm use stderr.
- D2. Quadratic in live data, stack overflow near 16k-deep data: `SemValue`
  (`lang/dynamics/src/syntax.rs:145`) derives `Clone` with boxed payloads, so every env lookup
  deep-copies. 5,000-cell list 2.4 s, 15,000 22 s, 20,000 aborts (exit 134). wasm: < 0.2 s.

## E. WebAssembly backends

- E1. Float `to_string` differs from interpreter/native on both wasm backends: `-0.0` prints `0`,
  `inf` prints `Infinity`, `1e21` in exponent form, Float32 at Float64 precision (`0.1+0.2` gives
  `0.30000001192092896`). `lang/tests/wasm-host.mjs` `installNumeric` uses JS `String()`.
- E2. wasm-am deep recursion (depth 100k) traps as bare `RuntimeError: unreachable at zydeco.zasm.push`
  with no message. The 1 MB stack is documented; the reporting is not.

## F. Formatter and CLI

- F1. Out-of-range float literals rewritten into unbound identifiers: `1e400` checks as Float64 but
  `fmt` prints `inf`, and the result fails "Unbound variable"; `-1e400` -> `-inf` does not lex;
  `1e-400` -> `0.0`. Preserve source text or reject non-finite literals.
- F2. Repo is not a fixpoint of its own formatter. `zydeco fmt --check` over tracked sources flags
  `lib/std/system/package.zy`, `lib/tests/monadic/{cbpv-monadic,cbv,free'}.zy`,
  `lib/tests/pack/named.zy`; four want a break inside `@(import(...))`. `fmt --check` also exits 0
  while listing files, contrary to its help text.
- F3. Formatter is exponential in redundant paren depth: `((((0))))` at 22 parens 12.6 s, >= 24 over
  20 s. Braces/tuples/applications fine.

## G. Diagnostics

- G1. Every `tyck.type-mismatch` has expected and found swapped: `let x : Int64 = "s"` reports
  "expected String, found Int64". Rendered at `check/error.rs:369`; caller passes the pair reversed.
- G2. Existential/seal mismatches print "expected X, found X" with no hint that two openings or two
  seals differ.
- G3. Value cycles in `begin` blocks report "seal the recursive type definition" or a bare sort
  mismatch instead of pointing at the cycle and suggesting `fix`.
- G4. Unknown string escapes silently drop the backslash (`"\q"` -> `q`, `"a\0b"` length 3);
  `\u{1F600}` is taken literally; `'\q'` becomes a backslash char. `lang/surface/src/textual/escape.rs`.
- G5. Unsolved inference variables leak as `Thk [fill-ty 3054068545599967056#0]`, always followed by
  a redundant "Missing solution for 1 hole(s)".
- G6. `run` on a non-OS program prints a raw `TypeId(...)`.
- G7. Parse errors are raw lalrpop strings with no ariadne snippet.
- G8. Lexer splits `0x1F` -> `0 x1F` and `1e` -> `1 e`.
- G9. `pack ... is Int64 where (0 : X)` silently discards the `: X` abstraction annotation (documented
  as sound, but no warning).
